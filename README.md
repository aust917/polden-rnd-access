# Заявки на доступ к polden-rnd

Открытая очередь заявок на доступ к закрытой базе R&D «Полдень» `aust917/polden-rnd`. В заявке только ник GitHub и имя; почта, токены и содержимое базы здесь не публикуются.

## Пользователю

Вставьте своему ИИ-агенту (Claude Code или Codex) на рабочем компьютере с Windows одну фразу:

> Подключи меня к базе R&D «Полдень» polden-rnd по инструкции https://github.com/aust917/polden-rnd-access#readme . Делай сам всё, что можешь. Меня спрашивай только о том, что нельзя узнать самому, и простыми словами объясняй, что нажать.

Лично вам придётся только:

1. Если нет аккаунта GitHub — зарегистрироваться и подтвердить почту (агент откроет страницу и подскажет по шагам).
2. Войти в GitHub: ввести в браузере код, который покажет агент.
3. Подождать, пока Артур одобрит заявку. Агент тем временем ставит программы.
4. Войти в Google Drive для компьютера под рабочей почтой `@polden.gg`.
5. Ответить на несколько вопросов: где хранить базу и кэш Google Drive, как вас подписывать в проектах, в каких папках вы работаете и как часто искать ваши новые исследования.
6. Нажать «Да», если Windows спросит разрешение на установку программы.

Пароли и коды агенту не сообщайте: их вводите только на сайтах GitHub и Google.

## Агенту: до получения доступа

Общайся по-русски, простыми словами. Делай сам всё, что можно проверить или выполнить на компьютере; человеку оставляй регистрацию, входы, коды и подтверждения Windows. Пароли и токены не запрашивай, не вводи и не ищи. Программы — только через WinGet или с официальных сайтов. Схема рассчитана на Windows; на другой системе остановись и сообщи.

### 1. Проверь компьютер и поставь недостающее

Проверь версию Windows, свободное место на локальных дисках и наличие: `winget`, Git (`git`), GitHub CLI (`gh`), Python 3.10+ (`python`, не заглушка Microsoft Store), Obsidian, Google Drive для компьютера (процесс `GoogleDriveFS`). Недостающее поставь сам:

```powershell
$w = '--exact', '--source', 'winget', '--accept-package-agreements', '--accept-source-agreements'
winget install --id Git.Git @w
winget install --id GitHub.cli @w
winget install --id Python.Python.3.13 @w
winget install --id Obsidian.Obsidian @w
winget install --id Google.GoogleDrive @w
$env:Path = [Environment]::GetEnvironmentVariable('Path', 'Machine') + ';' + [Environment]::GetEnvironmentVariable('Path', 'User')
```

Перед установкой сверь найденный пакет и издателя (`winget show --id …`). Без WinGet — официальные установщики: [Git](https://git-scm.com/install/windows), [GitHub CLI](https://cli.github.com/), [Python](https://www.python.org/downloads/windows/), [Obsidian](https://obsidian.md/download), [Google Drive](https://support.google.com/a/users/answer/13022292). Node.js для базы не нужен. Если Windows показывает запрос разрешения, скажи человеку: «Появится окно Windows с вопросом, разрешить ли установку. Нажмите “Да”».

### 2. GitHub: аккаунт и вход

Выполни `gh auth status`. Если вход уже выполнен — переходи к шагу 3.

Иначе спроси: «Есть ли у вас аккаунт на GitHub — сайте, где хранятся тексты нашей базы? Ответьте “Есть” или “Нет”».

- **Нет аккаунта.** Открой `Start-Process https://github.com/signup` и объясни: «Откроется регистрация GitHub. Введите почту (её не увидят другие участники), придумайте пароль и имя пользователя латиницей — это ваш ник. Пройдите проверку “я не робот” и введите код из письма GitHub. Когда увидите главную страницу GitHub, напишите “Готово”».
- **Вход.** Запусти `gh auth login --hostname github.com --git-protocol https --web`. Покажи человеку одноразовый код из вывода и скажи: «Откроется страница GitHub. Введите код `XXXX-XXXX`, нажмите Continue, затем Authorize github. Напишите “Вошёл”». Если браузер не открылся, дай адрес https://github.com/login/device .
- После входа: `gh auth setup-git` — Git будет использовать этот вход.

### 3. Ник, имя и доступ

```powershell
$login = gh api user --jq .login
$name = gh api user --jq .name
gh api repos/aust917/polden-rnd --jq .permissions.push
```

- Ответ `true` — доступ уже есть, переходи к шагу 6.
- Ответ 404 (`Not Found`) — доступа пока нет. Сначала проверь, нет ли уже приглашения (шаг 5), затем заявки.

Ник не спрашивай: он уже в `$login`. Если `$name` пустое, спроси: «Как вас представить в заявке? Напишите имя и фамилию так, как вас знают в команде. Их увидят все, кто откроет страницу заявок; почта туда не попадает».

### 4. Подай заявку (одну)

Сначала проверь свои прежние заявки:

```powershell
gh issue list -R aust917/polden-rnd-access --author '@me' --state all --json number,state,title,url,comments
```

- Есть **открытая** заявка — новую не создавай, жди её.
- Есть **закрытая** с комментарием «приглашён» или «уже отправлено» — переходи к шагу 5.
- Иначе создай:

```powershell
$body = "GitHub: @$login`nИмя: $name`n`nЗаявку подал ИИ-агент участника по инструкции подключения."
gh issue create -R aust917/polden-rnd-access --title "Доступ к polden-rnd: $login" --body $body
```

Повтор не страшен: GitHub Action закроет дубль. Скажи человеку: «Заявка на доступ отправлена: {ссылка}. Её одобрит Артур; когда это произойдёт, я сам приму приглашение. Пока продолжаю установку». Если человек знает, что Артур не видел заявку, предложи написать ему: «Артур, я подал заявку на доступ к polden-rnd: {ссылка}».

### 5. Пока ждёшь — Google Drive; затем прими приглашение

Пока заявка ждёт, подготовь Google Drive для компьютера: попроси человека открыть его и войти под **рабочей почтой `@polden.gg`**. Проверь, видна ли на диске Google Drive папка `Ω_RnD_media` на общем диске «Polden General» (раздел «Общие диски» / «Shared drives»).

- Рабочей почты `@polden.gg` нет — скажи: «Для общих файлов отдела нужна рабочая почта Полдня. Напишите Артуру: “Мне нужна рабочая почта @polden.gg и доступ к общему диску Polden General для базы polden-rnd”». Без неё продолжай установку текстов.
- Почта есть, а папки `Ω_RnD_media` не видно — скажи: «Напишите Артуру: “Выдайте, пожалуйста, доступ к общему диску Google Polden General для моей рабочей почты”». Свою папку вместо общей не создавай.

Приглашение проверяй раз в несколько минут:

```powershell
$id = gh api user/repository_invitations --jq '.[] | select(.repository.full_name == "aust917/polden-rnd") | .id'
if ($id) { gh api -X PATCH "user/repository_invitations/$id"; gh api repos/aust917/polden-rnd --jq .permissions.push }
```

Ответ `true` — доступ получен. Если одобрения за время сессии не было, скажи: «Заявка ждёт Артура. Когда придёт письмо GitHub о приглашении в polden-rnd, напишите мне “доступ дали” — продолжу с этого места». Заявку при этом не повторяй.

### 6. Получи базу и продолжай по её инструкции

Спроси, где хранить базу: покажи свободное место на дисках и предложи несистемный диск, например `D:\polden-rnd`. Папка не должна лежать внутри OneDrive, Google Drive или другого Git-репозитория.

```powershell
git clone --branch main https://github.com/aust917/polden-rnd.git '<папка>'
```

Дальше открой в базе `Исследования/Общее_пространство/Подключение_участника_Google_Drive.md` и продолжай по нему с раздела 4. Все остальные правила — в `AGENTS.md` базы.

## Для администратора

Каждая заявка — issue этого репозитория. GitHub Action:

- при подаче закрывает дубль открытой заявки того же автора, а также заявку уже участника или уже приглашённого;
- по метке **`одобрено`** от `aust917` приглашает **автора заявки** в `aust917/polden-rnd` с правом записи и закрывает заявку комментарием. Ник в тексте заявки ни на что не влияет;
- без секрета `POLDEN_RND_INVITE_TOKEN` пишет об этом в заявке и ничего не меняет.

Режим проверки: Actions → «Заявки на доступ» → Run workflow с номером заявки и `dry_run` — покажет в журнале, что было бы сделано.
